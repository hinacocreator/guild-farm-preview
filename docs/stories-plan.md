## 1. 目的

実際に滞在した方の取材記事で、サイトに足りていない2つを補います。

- **暮らしのイメージ** … 「1週間・1ヶ月をどう過ごすのか」は /life/ で説明していますが、
  説明よりも、実際に過ごした人の話のほうが伝わります。
- **信頼** … 現在 HOME / OWNER に置いている滞在者の言葉は3つの短い言葉だけです。
  誰が、いつ、どんな滞在をして、そう言ったのかが分かる記事があると裏づけになります。

### 絶対に守ること：架空の滞在者・体験談は作らない

- **想像で書いた滞在者・体験談・感想は1行も置きません。**
  写真だけ実在で本文が創作、というものも作りません。
- 取材していない段階で「サンプル記事」「ダミー記事」を公開状態にもしません
  （プレビュー用に置く場合も、本文に架空の人物像を書かず、レイアウト確認用のプレーンな文字で埋めます）。
- 本文は本人が話した内容のみ。読みやすさのための整えはしますが、
  言っていないことを足したり、意味が変わる要約はしません。

### 取材と許諾（実装の前提）

取材の設計は既存資料をそのまま使います（このリポジトリの外・GUILD Farm 本体の資料）:

- `/Users/conadesignstudio/Projects/guild-farm/sns/templates/interview-questions.md`
  - 声は**2種類**残す方針：**① 長尺インタビュー 3〜5分（初期・中盤・最終週の3回／記録用）** と
    **② 短答 1問10〜30秒（SNS素材用）**。記事の本文は主に①から起こします。
  - **いいことだけ言わせない。**「しんどかった」「合わないと思う」まで話してもらう。
    記事にも、合わない点・大変だった点を残します（そのほうが申込の質が上がるという方針）。
  - 「逆に、向いてないと思うのはどんな人？」の答えは、記事の中で使いどころが大きい質問です。
- `/Users/conadesignstudio/Projects/guild-farm/sns/content-planning.md`
  - **掲載許諾が、事例を使うことの前提**（許諾なしに参加者の声を使わない）。
  - **モニター滞在であることを隠さない。** 推奨表記は
    「※ モニター滞在としてご協力いただいています」。
    モニターの声を有料参加者の声と混ぜず、**「モニター参加者の声」と明示して区別する**。
  - 料金・生活費の金額は出さない（このサイトでは料金の数字は /plans/ のみ）。

実装に入れる条件（この3つが揃ってから）:

1. 実際の滞在者に取材が済んでいる（長尺インタビュー、または本人が書いた文章）。
2. **文章・写真それぞれについて、Webサイト掲載の許諾**が取れている（日付を記録する）。
3. モニター滞在かどうかがはっきりしている（モニターなら記事に明示する）。

## 3. データ構造案

`src/content/stories/<slug>.ts` を1記事1ファイルで置きます
（既存の `src/content/<page>.ts` と同じ「文章はコンテンツファイルに集める」方針のまま）。

```ts
// src/content/stories/<slug>.ts のかたち（案）
import type { ImageAsset } from "@/config/images";

export const story = {
  /** 記事タイトル。本人の言葉から取るのが理想 */
  title: "…",
  /** 滞在時期（例：2026年8月・1ヶ月滞在） */
  period: "2026年8月・1ヶ月滞在",
  /** 滞在プラン。"week" | "month" の2択（料金の数字は書かない） */
  plan: "month",
  /**
   * 本人の属性。⚠ 本人が公開に同意した範囲だけ。
   * 例：「20代・会社員・東京から」。氏名・勤務先・SNSアカウントは、
   * 本人が明示的に望んだ場合のみ。書かない選択（未記入）も可。
   */
  profile: "20代・会社員・東京から",
  /** 掲載許諾の記録。公開前チェックのための欄で、画面には出しません */
  consent: {
    /** 文章の掲載許諾日（YYYY-MM-DD） */
    textGrantedOn: "2026-09-01",
    /** 写真の掲載許諾日。撮影者・被写体どちらの同意も取れた日 */
    photoGrantedOn: "2026-09-01",
    /** モニター滞在か。true なら記事に「モニター滞在」と明示する */
    isMonitor: true,
  },
  /**
   * 本文。Q&A形式（取材をそのまま活かす）か、段落形式のどちらか。
   * 混在させたいので配列で持ちます。
   */
  body: [
    { kind: "qa", q: "なんで来ようと思った？", a: "…" },
    { kind: "paragraph", text: "…" },
  ],
  /** 写真。既存 images.ts と同じ ImageAsset 形式（{ src, alt }） */
  photos: [] as ImageAsset[],
  /** 公開状態。false のあいだは一覧・sitemap に出さない */
  published: false,
} as const;
```

補足:

- `photos` は `ImageAsset`（`src/config/images.ts` の `{ src: string; alt: string }`）と同じ形にします。
  ファイルは `public/images/stories/<slug>/…` に置く想定。**撮影者の同意と、写っている人の同意**の両方が必要です
  （HOME の H-08 に人物写真を入れていない理由と同じ）。
- `alt` は既存の写真と同じ書き方（何が写っているかの説明）で書きます。
- 記事の一覧順は `period` 順（新しい順）。一覧の元データは
  `src/content/stories/index.ts` で各 slug をまとめる形が素直です。
- `published: false` の記事は一覧・`sitemap` に出しません。

## 4. 表示部品案

`src/components/sections/stories/` 配下に置きます。既存部品を流用します。

### 一覧 `/stories/`

- ページ先頭は既存の **`PageHeader`**（`src/components/PageHeader.tsx` / props は `label` `title` `sub?` `lead`）。
- 記事カード（新規 `StoryCard.tsx`）= **`Photo`（`src/components/ui/Photo.tsx`）＋ 期間 ＋ 一言**。
  「一言」は本人の言葉から1行。カード全体、または `TextLink` で記事へ。
  レイアウトは `HomeValues` のグリッド（スマホ2列・PC12列）と同じ考え方で組めます。
- ページ末尾は既存の **`ClosingCta`**（`next` は `/plans/` を想定）。

### 記事 `/stories/<slug>/`

- **`PageHeader`**（`label="Stories"` / `title` は記事タイトル / `sub` に期間・属性 / `lead` に導入1〜2段落）。
- 本文 = Q&A または段落。Q&A の質問は小さめ、答えは本文サイズ。写真は段落のあいだに `Photo` で挟む。
- モニター滞在の場合、本文の近くに
  **「※ モニター滞在としてご協力いただいています」**を小さく添える（`AboutFit` の note と同じ扱い方）。
- 末尾に「**滞在した時期のプラン**」→ `/plans/` へのリンク（`TextLink`）。
  **プラン名（1週間滞在／1ヶ月滞在）までで、料金の数字は書きません。**
- ページ末尾は既存の **`ClosingCta`**。

metadata（title / description）は、他ページと同じく各記事のコンテンツファイルから `page.tsx` で export します。

## 5. 公開前チェック

記事を1本公開するたびに、上から順に確認します。

- [ ] **実在の滞在者の取材**である（架空の人物・創作の体験談が混ざっていない）
- [ ] **文章の掲載許諾**が取れている（`consent.textGrantedOn` に日付が入っている）
- [ ] **写真の掲載許諾**が取れている（撮影者の同意＋写っている人全員の同意／`consent.photoGrantedOn`）
- [ ] **モニター滞在なら、記事にそう明示している**（有料参加者の声と混ぜていない）
- [ ] **料金の数字を書いていない**（金額は /plans/ のみ。生活費の合計額もこのサイトでは出さない）
- [ ] **個人情報**を書いていない（氏名・勤務先・住所・SNSアカウント・写真の背景に写った表札や車のナンバーを含む）
- [ ] 本人が読んで **「これで出してよい」と確認した文面**である（公開後の取り下げ依頼にも応じる）
- [ ] 就農・移住ができるという約束になっていない（`content-planning.md` の「書かないこと」）
- [ ] サイトの他ページと**事実が矛盾していない**（プラン・滞在先・畑の場所など）
